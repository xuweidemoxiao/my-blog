## ArticleCreate 页面高度链修复
- 需求：让 ArticleCreate 页面继承 router-view 的高度，使编辑器撑满视口剩余空间。
- 关键结论：vue-router 的 RouterView 设了 `inheritAttrs: false`，会把 attrs/class 透传合并到被渲染组件的根元素上，因此 `<router-view class="flex-1">` 的 class 实际落在页面根 div 上。
- **真正的坑**：`/article/create` 路由挂在 `BlankLayout`（不是 DefaultLayout）下，而 BlankLayout 里包了一层没有高度的 `<div>`，`h-full` 相对它解析直接塌成内容高度。教训：排查高度链必须先看路由实际命中的是哪个 layout。
- 改动：
  - `src/layout/BlankLayout.vue`：根 div 加 `h-full flex flex-col`，内部 `<router-view>` 加 `flex-1 min-h-0`（用 flex 解析而非百分比，更稳）。
  - `src/views/ArticleCreate.vue`：根 div 加 `h-full flex flex-col`，header 加 `shrink-0`，ArticleEditor 加 `flex-1 min-h-0`。
  - `src/components/Article/ArticleEditor.vue`：根卡片加 `flex flex-col`，内层内容容器加 `flex-1 min-h-0`（两个 textarea 原本就有 `flex-1 min-h-0`，链路补好后生效）。
- 验证：playwright-core + 本机 Edge 实测 1280×720 视口：App 根 720 → BlankLayout 652 → 页面根 620 → 编辑器卡片 572 → textarea 167/181，截图存于 `.workbuddy/article-create-verify.png`。
- 项目模式：编辑类页面用「h-full + flex flex-col + flex-1/min-h-0」逐层传递高度；组件自身负责内部 flex 布局，父级只传尺寸类（flex-1 min-h-0）。BlankLayout 同样被 /gallery/create 使用，链路已通用。

## autoResize 撑页面 bug 修复（下午）
- 现象：内容框输入后页面被撑高（实测 720→3914），删空后不恢复。
- 根因：①autoResize 给 textarea 设行内 height，用户删除了 textarea 的 flex-1 后行内高度成为 flex 基准尺寸；②App 根 `min-h-screen` 高度是 intrinsic 计算，该高度顺着 flex 链向上传播，`min-h-0` 拦不住 intrinsic 传播（实测 overflow:hidden/max-h:100% 均无效，`contain:size` 有效）。
- 修复（`ArticleEditor.vue`）：内容区 div 加 `[contain:size]`；简介 textarea 加 `shrink-0`（防止被等比收缩压成 4px）。
- 验证：灌 1500 字 docScrollH 保持 720、内容框 306px 内部滚动；删空恢复 56px；90 字正常长高到 84px。截图 `.workbuddy/article-create-autoresize-fixed.png`。
- 过程中用户多次手工重构：BlankLayout 精简为裸 `<router-view>`、删除页面根 h-full、把 px-60/py-4 从组件挪到使用方。改文件前必须先 Read 最新内容。

## ArticleEditor autoResize 根因修复（最终）
- 用户指出之前 `[contain:size]` 只是摁住症状，真正问题是 Textarea 删内容后高度没收缩。
- 复现：playwright 在 1600×900 下，60 行内容 → textarea 1680px，page 2094px；删空后 textarea 仍是 1680px，page 仍是 2094px。
- 根因：PrimeVue `resize()` 里 `needsShrinking = currentHeightValue && scrollHeight < currentHeightValue`，`scrollHeight` 读取于行内高度 reset 之前，而 `scrollHeight >= clientHeight` 恒成立；当行内高度已经 1680px 时，`scrollHeight` 至少也是 1680px，收缩分支成为死代码。
- 修复：`src/components/Article/ArticleEditor.vue`
  - 移除内容框的 `autoResize`。
  - 加 `ref="contentTextarea"`。
  - 用 `watch(content)` + `nextTick` + `ResizeObserver(rAF)` 自己调整高度：`el.style.height = 'auto'; el.style.height = el.scrollHeight + 'px';`。
  - `:pt` 里给内容框加 `overflow: hidden;` 避免 resize 瞬间出滚动条。
- 验证：删空后 textarea 回到 56px，page 回到 900px（视口高度），重新输入 30 行又长到 840px，无 console 错误。截图存 `outputs/shot_*.png`。
- **补充（用户自行定位到更精确的触发点）**：真正的直接原因是 `:pt` 里把 textarea 的 `border` 设成了 0。box-sizing:border-box 下 `clientHeight = 行内高度 − border`，而 `scrollHeight >= clientHeight`；border=0 时 clientHeight 恰等于行内高度，`scrollHeight < 行内高度` 恒为 false。border>0（默认 2px）时才有余量让判断成立。最小对照实验：border:0 → 2640<2640 false；border:1px → 2638<2640 true。padding:0 不影响（两边都含 padding，相减抵消）。
